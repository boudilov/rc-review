# RC REVIEW — прогресс и заметки для продолжения работы

Презентация о работе ресурсных центров (РЦ) UCampus. Живой сайт: `index.html` +
`pages/NN/index.html` (по одному фрагменту на страницу), стилистика — `styles.md`.
Репозиторий: https://github.com/boudilov/rc-review (публичный).

## Как запустить

```bash
cd RC_Review
python -m http.server 8936
```
Открыть `http://localhost:8936`. Конфиг превью уже лежит в `.claude/launch.json`.

## Архитектура (важно помнить)

- **Один файл — один каркас, остальное — фрагменты.** `index.html` — тулбар
  (40 сегментов-страниц, слева бренд «RC REVIEW», справа кнопка `i` со
  списком горячих клавиш) + JS-загрузчик, который через `fetch` подтягивает
  `pages/NN/index.html` в контейнер активной страницы. Общее число страниц
  задано в JS как `var TOTAL = 40;` — при добавлении страниц сверх этого
  число нужно поднимать вместе с кнопками-сегментами и `<section
  class="page">`-контейнерами (все три места правятся синхронно).
- **Фрагменты — это только HTML+CSS, БЕЗ рабочего JS.** `<script>` внутри
  фрагмента, вставленного через `innerHTML`, не выполняется браузером —
  это ограничение архитектуры, не баг. Поэтому все интерактивные штуки на
  страницах статистики (модалки, тумблеры raw/normalized, скрытие лейблов)
  сделаны чистым CSS: `:target` для модалок, `:checked` + `~`/`:has()` для
  тумблеров, `:hover` для тултипов и подсветки.
- **Кэш — частый источник багов.** Каждый `fetch` фрагмента и каждая
  `<img>`/`<iframe>` внутри него дозаписывается query-параметром
  `?_=Date.now()` (см. `loadPage()` в `index.html`), иначе браузер может
  показывать старую версию файла после правки на диске. Если правишь
  что-то и не видишь изменений — сначала подозревай кэш, а не логику.
- **id должны быть уникальны по всему документу**, а не только в рамках
  одной страницы — все 40 фрагментов одновременно живут в DOM (просто
  скрыты `display:none`). Модалки на разных страницах используют префиксы
  `p{N}m{i}` (`p11m3`, `p16m1` и т.д.), чтобы не коллизировать через
  `:target`/одинаковый `#hash`.
- **Курсор** везде переопределён на маленькую полупрозрачную точку
  (SVG data-URI в `<html,body>` в `index.html`).
- **Раздел `pages/rc-app/`** — отдельное веб-приложение (история РЦ +
  орг-структура), встроено на страницы 5 и 6 через `<iframe>` (не
  фрагмент), т.к. ему реально нужен работающий JS. Два входа:
  `history.html`/`history-main.js` и `structure.html`/`structure-main.js`,
  общие модули `app.js`/`parser.js`/`layout.js`/`viz.js`. Исходники
  `structure.xlsx`/`history.xlsx` + `convert.py` лежат там же — чтобы
  обновить историю/структуру, правишь xlsx и гоняешь `python convert.py`
  внутри `pages/rc-app/`.
- **Раздел `pages/ucampus-viz/`** — второе embedded-приложение того же
  типа (внешний проект, не фрагмент, свой `<html>`), встроено на стр. 31
  через `<iframe>`. См. таблицу «Что сделано по страницам» → стр. 31.

## Переиспользуемые CSS-паттерны

- `.accent-group` + `.accent-item` — при наведении на элемент внутри
  группы остальные элементы группы тускнеют (`opacity`), у наведённого —
  `text-shadow`-свечение. Определено в `index.html`, работает на любой
  странице.
- **CSS-модалка без JS**: `<a href="#id">` → `<div class="...-modal"
  id="id">` с `display:none; :target{display:flex}`, закрытие — клик по
  фону/крестику (`href="#"`). Использовано на страницах 11, 12–17, 20.
- **Тумблер без JS**: скрытый `<input type="checkbox">` + `<label
  class="...-switch">` (тот же трек+квадратный бегунок, что в
  `styles.md`); переключение видимости — `body:has(#id:checked) .foo
  {display:...}`. Был реализован (раз) на прототипе Summary для 12–17,
  но пользователь попросил откатить — паттерн рабочий, можно вернуть.
- **Скрытие подписи, если не влезает + tooltip по hover** — на
  страницах 12–17: для каждого сегмента бара считается влезает ли текст
  (эвристика по кол-ву символов × средняя ширина символа для шрифта), если
  нет — подпись не рисуется, вместо неё `.stat12-seg-tip` (`opacity:0`,
  `:hover{opacity:1}`). Сегмент/бар получают `overflow:hidden` в покое и
  `overflow:visible` по hover (плюс `.bar:has(.seg:hover){overflow:visible}`),
  чтобы тултип не обрезался.
- **Монохромные графики**: alpha кодирует величину (не цвет). Для
  сравнения ОДНОГО набора данных между категориями — нормализация в
  ОБЩЕМ масштабе (шкала считается по всем категориям сразу), иначе
  яркость несравнима.
- Плавные линии на графиках — сглаживание Catmull-Rom → кубические
  Bezier, генерируется офлайн в Python (не в браузере), путь `d`
  вставляется как статика в SVG.

## Источники данных

- `Stats 2026/*.xlsx` — по каждой мастерской (01–10) файлы `CLASS`/`SELF`/
  `IDLE`; по прокату (`11_Прокат_*`) — `BOOKINGS`/`IDLE`/`RESOURCES`/`SELF`.
  Копия лежит **внутри репозитория** (публично!) — так решил пользователь
  осознанно, несмотря на предупреждение о чувствительности данных.
- Учебный год = 1 авг — 31 июля. «Прошлый» = 2024/25, «прошедший»/«этот» =
  2025/26 (на момент работы — текущая дата в сессии была 2026-08-25).
- CLASS/SELF файлы мастерских: колонки `Юр.лицо`, `Школа`, `Направление`,
  `Программа`, `Период` (YYYY-MM), `Часы`. Один ряд = агрегат часов по
  (юрлицо×школа×направление×программа) за месяц, НЕ отдельная бронь —
  посчитать точное число броней из этих данных нельзя, только часы.
- Прокат `RESOURCES`: `Месяц`, `Ресурс`, `Школа`, `Программа`, `Кол-во`,
  `Юрлицо` — нет колонки `Направление`, поэтому на странице 19 разрез по
  направлениям взят из `SELF`-файла проката (другая единица измерения:
  часы, а не «Кол-во»; это явно подписано на странице).
- `IDLE`-файлы (по одному на мастерскую 01–10 + прокат 11): колонки
  `Интервал` (YYYY-MM), `Доступное время (ч)`, `Занятое время (ч)`,
  `Свободное время (ч)`, `Процент занятости`, `Процент простоя`.
  «Занятое» и «свободное» не всегда в сумме дают «доступное» (разные
  методики подсчёта пересекающихся броней) — на страницах 21–22 не
  пересчитывается, берутся готовые часы `Доступное`/`Свободное`
  (простой% = свободное/доступное, часо-взвешенно по году, а не среднее
  готовых процентов по месяцам). Август систематически даёт простой
  70–100% почти у всех мастерских — сезонный провал (лето/начало года),
  это не аномалия данных.
- `Stats 2026/Originals/` — те же данные с англ. именами файлов, для
  сверки; не менять, не использовать напрямую.

## На заметку на будущее

- При правке чисел/графиков через Python-скрипты — они писались как
  одноразовые файлы в scratchpad, в репозитории не сохранены. Если нужно
  пересчитать что-то похожее — проще написать заново по описанным выше
  паттернам (pandas groupby по нужной колонке, Catmull-Rom для линий).
- Прежде чем коммитить новые сырые данные — если они большие/чувствительные,
  сначала спросить пользователя (см. историю с `Stats 2026` и
  `structure.xlsx`, 22 МБ).
- Названия мастерских (для консистентности везде): Одежда, Текстиль,
  Печать, 3D, Ювелирная, Керамика, Артплей, Фабрика, Тёмная комн.,
  Принт-офис (индексы 01–10 в этом порядке; 11 = Прокат, обрабатывается
  отдельно).
